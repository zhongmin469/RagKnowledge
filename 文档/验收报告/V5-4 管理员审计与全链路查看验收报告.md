## 1. 验收口径

本阶段解决的不是文案问题，而是语义矛盾：

| 原状态 | 问题 |
|---|---|
| `DELETE /api/me/io-logs` 物理删除 `chat_io_log` / `llm_call_log` | 删除后管理员真的查不到，与“管理员可查全链路”定位冲突 |
| 删除会话连带物理删除该会话 `chat_io_log` | 运行日志链路断档，事故无法回溯 |
| 删除动作不写审计 | 管理员不知道谁在何时删了什么 |
| 确认弹窗写“管理员也无法查到” | 对外承诺与产品能力相反 |
| `operation_log` 已写入 20 类动作，无任何查询接口 | “只写不查”，审计价值为零 |

本阶段验收口径：

- 用户删除 = **从本人视角删除**（`mode=soft`），用户侧不可见、不可导出；管理员在 `IO_LOG_RETENTION_DAYS`（当前 90 天）内仍可查看，并在列表标「用户已删除」。
- 管理员对他人数据**只读**：不改、不删、不代发、不冒充。
- 所有跨用户读取写 `ADMIN_VIEW_USER_DATA`，60 秒内同对象去重。
- 不新增错误码，不改变已有错误码含义。

### 关键修复（开发过程踩坑）

1. `activity` 的 SQL 中 `LIKE '%EXPORT%'` 被 psycopg3 当占位符，报 `ProgrammingError: only '%s','%b','%t' are allowed, got '%E'` —— 改为 `'%%EXPORT%%'`。
2. 新接口 `_date` 初版只校验长度，`2026-13-01` 会落到 SQL 才 503 —— 改为 `datetime.strptime` 严格校验，直接返 `40001`。
3. Windows 下裸 `uvicorn` 必失败：ProactorEventLoop 不被 psycopg 支持，lifespan 直接退出 —— 必须用 `backend/scripts/run_dev.py`（`SelectorEventLoop`），端口用 `APP_PORT` 覆盖。
